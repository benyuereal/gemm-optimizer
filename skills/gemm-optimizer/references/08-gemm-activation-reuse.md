# 08 · GEMM 为什么复用激活（线性投影视角）

> 一句话结论：GEMM 把输入元素从原始特征空间**线性投影**到由权重行向量定义的新特征空间
> （`Y = X @ Wᵀ`）。投影时**激活 `X[m,k]` 被复用 N 次、权重 `W[n,k]` 被复用 M 次**；
> decode 下 **N ≫ M**（M 仅 1~32，N ≥ 4096），所以激活的复用价值远高于权重。
> 优化的核心方向因此是：**让激活常驻片上、减少激活的全局内存加载**——这正是 07 篇
> slc（evict-first）优化的动机来源。

## 1. GEMM 的意义：线性投影

GEMM 把输入元素从原始特征空间，线性投影到由权重行向量定义的新特征空间。

**数据示例**：

- 激活 `X`：`[M=2, K=4]`，2 个元素，每个 4 个原始特征。
- 权重 `W`：`[N=3, K=4]`，3 个输出特征方向，每个方向 4 维。

```
X = [1.0  0.5  0.8  0.2]      W = [ 0.8 -0.2  0.5  0.1]
    [0.2  0.9  0.1  0.7]          [-0.3  0.9  0.2 -0.4]
                                  [ 0.1  0.3 -0.7  0.6]
```

`W` 的每一行是一个特征方向（如"科技""体育""娱乐"）。
`Y = X @ Wᵀ` 的每个值 = 元素向量与某个特征方向的**点积**，即该元素在该方向上的**投影强度**。

## 2. 激活与权重的布局（结合数据）

**激活 X**：`[M=2, K=4]`，行主序，**动态生成**（每行一个 token，每列一个原始特征）。

```
token0: [1.0, 0.5, 0.8, 0.2]
token1: [0.2, 0.9, 0.1, 0.7]
```

**权重 W**：`[N=3, K=4]`，行主序，**静态可预打包**（每行一个输出特征方向，每列一个原始特征）。

```
维度0: [ 0.8, -0.2,  0.5,  0.1]
维度1: [-0.3,  0.9,  0.2, -0.4]
维度2: [ 0.1,  0.3, -0.7,  0.6]
```

**转置 Wᵀ**：`[K, N]`，用于矩阵乘法。

```
Wᵀ = [ 0.8  -0.3   0.1 ]
     [-0.2   0.9   0.3 ]
     [ 0.5   0.2  -0.7 ]
     [ 0.1  -0.4   0.6 ]
```

## 3. GEMM 运算的最终效果

计算 `Y = X @ Wᵀ`，`Y` 形状 `[M=2, N=3]`。

**元素0**：

- 维度0（科技）：`1.0×0.8 + 0.5×(-0.2) + 0.8×0.5 + 0.2×0.1 = 1.12`
- 维度1（体育）：`1.0×(-0.3) + 0.5×0.9 + 0.8×0.2 + 0.2×(-0.4) = 0.23`
- 维度2（娱乐）：`1.0×0.1 + 0.5×0.3 + 0.8×(-0.7) + 0.2×0.6 = -0.19`

**元素1**：

- 维度0（科技）：`0.2×0.8 + 0.9×(-0.2) + 0.1×0.5 + 0.7×0.1 = 0.10`
- 维度1（体育）：`0.2×(-0.3) + 0.9×0.9 + 0.1×0.2 + 0.7×(-0.4) = 0.49`
- 维度2（娱乐）：`0.2×0.1 + 0.9×0.3 + 0.1×(-0.7) + 0.7×0.6 = 0.64`

结果矩阵：

```
Y = [1.12  0.23 -0.19]
    [0.10  0.49  0.64]
```

**效果**：

- 元素0 在"科技"上得分 1.12，特征最强。
- 元素1 在"娱乐"上得分 0.64，特征最强。

投影后的 `Y` 就是元素在新特征空间中的表达。

## 4. 为什么一般都是复用激活（结合数据）

**复用次数公式**：

- 激活 `X[m, k]` 参与所有 `n` 的计算 → 复用 **N 次**。
- 权重 `W[n, k]` 参与所有 `m` 的计算 → 复用 **M 次**。

**用数据验证**：

- `X[0,0] = 1.0` 参与 `Y[0,0]`、`Y[0,1]`、`Y[0,2]` → 复用 **3 次**（N=3）。
- `W[0,0] = 0.8` 参与 `Y[0,0]`、`Y[1,0]` → 复用 **2 次**（M=2）。

**LLM 实际场景**：

| 场景 | M | N | 激活复用 | 权重复用 |
|------|---|---|:---:|:---:|
| Prefill | batch×seq_len，可达数千 | 隐藏维度 4096~11008 | 例 M=4096,N=11008 → **11008 次** | 4096 次 |
| Decode | batch×1，通常 1~32 | 仍 4096 以上 | 例 M=1,N=4096 → **4096 次** | 1 次 |

> Prefill 下 M 也可上千，激活复用仍 ≥ 权重；但 **Decode 下 M 极小（1~32）、N 仍 ≥ 4096**，
> N ≫ M 的差距被拉满——这正是 slc 主要针对的场景。

**优化策略**：

GEMM 分块（tiling）时，把**激活块 `[BM, BK]`** 留在共享内存/寄存器，与多个**权重块 `[BK, BN]`**
相乘。由于 **N ≫ M**（decode 阶段尤其明显），激活的复用价值远高于权重，因此
**优先保证激活在片上、减少激活的全局内存加载**，是提升性能的关键。

> 承上：这解释了 07 篇里"为什么缓存中该留的是激活（小 + 高复用）、该赶的是权重
> （524MB 大流 + 一次性）"——slc 给权重 load 打 evict-first，正是为了让这块反复读的
> 激活在 L2 里站稳位置。位级细节（word0 bit17、两种指令形态）见 07 篇，此处不重复。

## 5. 量化粒度：per-token / per-channel / per-group

低比特存储（如 int8）时，用**缩放因子 scale** 在"整数 ↔ 真实浮点"之间换算。
scale 的**粒度**（一个 scale 管多少个数）决定精度与查表开销的平衡。沿用 §2 的小数据。

### 5.1 激活：per-token（每个 token 一个 scale）

激活按行（token）量化，一行一把尺子：

```
token0 scale = max(1.0, 0.5, 0.8, 0.2) / 127 = 1.0 / 127
token1 scale = max(0.2, 0.9, 0.1, 0.7) / 127 = 0.9  / 127
```

反量化：`X_hat[m,k] = q_x[m,k] * scale_x[m]`（shape `[M]`）。

### 5.2 权重：per-channel（每一行一个 scale）

每行所有 K 个特征**共用一个**缩放因子：

```
维度0: max=0.8 → scale = 0.8 / 127
维度1: max=0.9 → scale = 0.9 / 127
维度2: max=0.7 → scale = 0.7 / 127
```

反量化：`W_hat[n,k] = q_w[n,k] * scale_w[n]`（scale shape `[N]`）。

### 5.3 权重：per-group（每一行再切成小组，每组一个 scale）

设 group size **G=2**，每行 4 个特征切成 2 组，**每组一把尺子**：

```
维度0: 组0=[0.8,-0.2] max=0.8 → scale = 0.8 / 127
       组1=[0.5, 0.1] max=0.5 → scale = 0.5 / 127
维度1: 组0=[-0.3,0.9] max=0.9 → scale = 0.9 / 127
       组1=[0.2,-0.4] max=0.4 → scale = 0.4 / 127
维度2: 组0=[0.1, 0.3]  max=0.3 → scale = 0.3 / 127
       组1=[-0.7,0.6] max=0.7 → scale = 0.7 / 127
```

反量化：`W_hat[n,k] = q_w[n,k] * scale_w[n, k//G]`（scale shape `[N, K/G]`）。

### 5.4 对比

| 粒度 | 一个 scale 管多少 | scale 数量 | 精度 / 开销 |
|------|------------------|:---:|------|
| **per-channel** | 一整行（K 个数） | `[N]` | 粗；查表最省 |
| **per-group** | 一行内一段（G 个数） | `[N, K/G]` | 更细，更能贴合局部数值差异，精度更高；scale 变多，反量化查表开销更大 |

> 分组越细（G 越小），越能适应行内不同区段的数值范围，精度越高，但 scale 数量与
> 反量化时的查表/乘 scale 开销也随之上升。G=K 退化回 per-channel。
