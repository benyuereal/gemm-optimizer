# 08 · GEMM 为什么复用激活（线性投影视角）

> 一句话结论：GEMM 把输入元素从原始特征空间**线性投影**到由权重行向量定义的新特征空间
> （`Y = X @ Wᵀ`）。投影时**激活 `X[m,k]` 被复用 N 次、权重 `W[n,k]` 被复用 M 次**；
> decode 下 **N ≫ M**（M 仅 1~32，N ≥ 4096），所以激活的复用价值远高于权重。
> 优化的核心方向因此是：**让激活常驻片上、减少激活的全局内存加载**——这正是 07 篇
> slc（evict-first）优化的动机来源。

## 1. GEMM 的意义：线性投影

GEMM 把输入元素从原始特征空间，线性投影到由权重行向量定义的新特征空间。

**数据示例**：

- 激活 `X`：`[M=2, K=4]`，2 个元素，每个 4 个原始特征。
- 权重 `W`：`[N=3, K=4]`，3 个输出特征方向，每个方向 4 维。

```
X = [1.0  0.5  0.8  0.2]      W = [ 0.8 -0.2  0.5  0.1]
    [0.2  0.9  0.1  0.7]          [-0.3  0.9  0.2 -0.4]
                                  [ 0.1  0.3 -0.7  0.6]
```

`W` 的每一行是一个特征方向（如"科技""体育""娱乐"）。
`Y = X @ Wᵀ` 的每个值 = 元素向量与某个特征方向的**点积**，即该元素在该方向上的**投影强度**。

## 2. 激活与权重的布局（结合数据）

**激活 X**：`[M=2, K=4]`，行主序，**动态生成**（每行一个 token，每列一个原始特征）。

```
token0: [1.0, 0.5, 0.8, 0.2]
token1: [0.2, 0.9, 0.1, 0.7]
```

**权重 W**：`[N=3, K=4]`，行主序，**静态可预打包**（每行一个输出特征方向，每列一个原始特征）。

```
维度0: [ 0.8, -0.2,  0.5,  0.1]
维度1: [-0.3,  0.9,  0.2, -0.4]
维度2: [ 0.1,  0.3, -0.7,  0.6]
```

**转置 Wᵀ**：`[K, N]`，用于矩阵乘法。

```
Wᵀ = [ 0.8  -0.3   0.1 ]
     [-0.2   0.9   0.3 ]
     [ 0.5   0.2  -0.7 ]
     [ 0.1  -0.4   0.6 ]
```

## 3. GEMM 运算的最终效果

计算 `Y = X @ Wᵀ`，`Y` 形状 `[M=2, N=3]`。

**元素0**：

- 维度0（科技）：`1.0×0.8 + 0.5×(-0.2) + 0.8×0.5 + 0.2×0.1 = 1.12`
- 维度1（体育）：`1.0×(-0.3) + 0.5×0.9 + 0.8×0.2 + 0.2×(-0.4) = 0.23`
- 维度2（娱乐）：`1.0×0.1 + 0.5×0.3 + 0.8×(-0.7) + 0.2×0.6 = -0.19`

**元素1**：

- 维度0（科技）：`0.2×0.8 + 0.9×(-0.2) + 0.1×0.5 + 0.7×0.1 = 0.10`
- 维度1（体育）：`0.2×(-0.3) + 0.9×0.9 + 0.1×0.2 + 0.7×(-0.4) = 0.49`
- 维度2（娱乐）：`0.2×0.1 + 0.9×0.3 + 0.1×(-0.7) + 0.7×0.6 = 0.64`

结果矩阵：

```
Y = [1.12  0.23 -0.19]
    [0.10  0.49  0.64]
```

**效果**：

- 元素0 在"科技"上得分 1.12，特征最强。
- 元素1 在"娱乐"上得分 0.64，特征最强。

投影后的 `Y` 就是元素在新特征空间中的表达。

## 4. 为什么一般都是复用激活（结合数据）

**复用次数公式**：

- 激活 `X[m, k]` 参与所有 `n` 的计算 → 复用 **N 次**。
- 权重 `W[n, k]` 参与所有 `m` 的计算 → 复用 **M 次**。

**用数据验证**：

- `X[0,0] = 1.0` 参与 `Y[0,0]`、`Y[0,1]`、`Y[0,2]` → 复用 **3 次**（N=3）。
- `W[0,0] = 0.8` 参与 `Y[0,0]`、`Y[1,0]` → 复用 **2 次**（M=2）。

**LLM 实际场景**：

| 场景 | M | N | 激活复用 | 权重复用 |
|------|---|---|:---:|:---:|
| Prefill | batch×seq_len，可达数千 | 隐藏维度 4096~11008 | 例 M=4096,N=11008 → **11008 次** | 4096 次 |
| Decode | batch×1，通常 1~32 | 仍 4096 以上 | 例 M=1,N=4096 → **4096 次** | 1 次 |

> Prefill 下 M 也可上千，激活复用仍 ≥ 权重；但 **Decode 下 M 极小（1~32）、N 仍 ≥ 4096**，
> N ≫ M 的差距被拉满——这正是 slc 主要针对的场景。

**优化策略**：

GEMM 分块（tiling）时，把**激活块 `[BM, BK]`** 留在共享内存/寄存器，与多个**权重块 `[BK, BN]`**
相乘。由于 **N ≫ M**（decode 阶段尤其明显），激活的复用价值远高于权重，因此
**优先保证激活在片上、减少激活的全局内存加载**，是提升性能的关键。

> 承上：这解释了 07 篇里"为什么缓存中该留的是激活（小 + 高复用）、该赶的是权重
> （524MB 大流 + 一次性）"——slc 给权重 load 打 evict-first，正是为了让这块反复读的
> 激活在 L2 里站稳位置。位级细节（word0 bit17、两种指令形态）见 07 篇，此处不重复。

## 5. 落到真实 CTA：tiling 把「逻辑复用」变成「物理读取」

§4 的「激活复用 N 次 / 权重复用 M 次」是**按输出元素**数出来的逻辑复用。真实 kernel 不逐元素算，而是**分块（tiling）后按 CTA 算**——逻辑复用要换算成每个 CTA 实际从 HBM 读多少。本节用本 GEMM 的真实 tile 做这个换算（完整 grid 图见 07 篇 §1.5）。

**三个方向都切，但性质不同（本 GEMM：M=32，N=51200，K=5120）：**

| 维度 | 尺寸 | tile | 怎么切 | 切完是什么 |
|---|---|---|---|---|
| M | 32 | BM=128 | `ceil(32/128) = 1` | **1 个 M-tile**（32 行有效，96 行空跑） |
| N | 51200 | BN=32 | `51200/32 = 1600` | **1600 个 N-tile → 1600 个 CTA**（空间并行） |
| K | 5120 | BK=128 | `5120/128 = 40` | **40 步，CTA 内部串行累加（K-loop）** |

- **M / N 切块 = 空间并行**：切出的 tile 分给不同 CTA 同时跑；`grid = ceil(M/BM) × (N/BN) = 1 × 1600 = 1600` 个 CTA。
- **K 切块 = 时间串行（K-loop）**：输出 `Y[m,n] = Σ_k X[m,k]·W[n,k]` 的 K 向累加塞不进单条 MMAC，于是沿 K 切 `BK=128` 的块，一块块喂进寄存器累加。

**一个 CTA 内部 = K-loop（沿 K 分 40 步累加）：**

```
一个 CTA 只算自己那块 [32, 32] 输出
  acc[32,32] = 0
  for k in 0..40:                        # K = 5120 ÷ BK=128 → 40 步
     A_tile[32,128] ← 激活 (BM, BK)      # 1600 个 CTA 读同一块
     W_tile[128,32] ← 权重 (BK, BN)      # 各 CTA 读自己那片
     acc += A_tile @ W_tile
```

**复用落到物理读取（关键换算）：**

| | 谁读 | 读什么 | 物理读取 |
|---|---|---|---|
| 激活 A | 1600 个 CTA 都读 | 同一块 `A[32, 5120]`（M 只有 1 个 tile） | **横向 1600×**（= `N/BN`） |
| 权重 W | 每个 CTA 读自己那片 | `W[5120, 32]`，1600 片互不相同 | **纵向各 1×**（片间零复用） |

**逻辑复用 → 物理读取的桥：**

- 激活逻辑上参与 `N = 51200` 个输出 → 物理读 `N/BN = 51200/32 =` **1600 次**（每个 N-tile CTA 读一遍）。
- 权重逻辑上参与 `M = 32` 个输出 → M 只有 1 个 M-tile，每片权重被 1 个 CTA 独占读 → **1 次**。

一句话：**M/N 切成空间并行摊给 CTA，K 切成 40 步在 CTA 内部循环累加；§4「激活复用 N 次、权重 M 次」落到 `BN=32` 的 grid 上，就是「激活物理读 1600 次、权重每片读 1 次」——这正是第 2 节「524 MB 大流 vs 327 KB 复用 1600 次」在读取次数上的具体化，也是 slc 只给权重（1 次、纯流式）打 evict-first 的原因。**

### 5.1 用 §1 的小数据把 tiling 走一遍（M=2, N=3, K=4）

上一段用的是真实 GEMM（1600 CTA、40 步 K-loop），规模太大没法手算。这里换 **§1 的小数据**（`X[2,4]`、`W[3,4]`）把**同一套 tiling 机制**走一遍，选能在纸上逐步核对的 tile，最后拼出来的 `Y` 与 §3 的数值**逐位一致**。

**切分规模与 grid（小数据版）：**

| 维度 | 尺寸 | tile | 怎么切 | 切完是什么 |
|---|---|---|---|---|
| M | 2 | BM=2 | `ceil(2/2) = 1` | **1 个 M-tile**（X 全部 2 行都归 N-tile#0） |
| N | 3 | BN=2 | `ceil(3/2) = 2` | **2 个 N-tile → 2 个 CTA**（N-tile#0 覆盖维度 0,1；N-tile#1 覆盖维度 2） |
| K | 4 | BK=2 | `4/2 = 2` | **2 步 K-loop（每个 CTA 内部串行累加）** |

`grid = 1 × 2 =` **2 个 CTA**。M 只有 1 个 tile，所以每个 K-step 的 `A_tile` 是**两个 CTA 共读的**；`W_tile` 各读各的片。

**两个 CTA 共读的 A_tile（横向复用，各 K-step 都读同一块）：**

```
K-step 0 (k=0..1):            K-step 1 (k=2..3):
A_tile[2,2] = [1.0  0.5]      A_tile[2,2] = [0.8  0.2]
              [0.2  0.9]                  [0.1  0.7]
```

**CTA#0（N-tile#0，算 `Y[:, 0..1]`）：**

```
W_tile step0 = [ 0.8 -0.3]    step0 部分积 A_tile@W_tile = [ 0.70   0.15]
            [-0.2  0.9]                            [-0.02   0.75]
W_tile step1 = [ 0.5  0.2]    step1 部分积                   [ 0.42   0.08]
            [ 0.1 -0.4]                             [ 0.12  -0.26]

acc = step0 + step1 = [ 1.12   0.23]
                      [ 0.10   0.49]
```

抽一格验证：`acc[0,0] = (1.0×0.8 + 0.5×(-0.2)) + (0.8×0.5 + 0.2×0.1) = 0.70 + 0.42 = 1.12` ✓

**CTA#1（N-tile#1，算 `Y[:, 2]`，BN 方向只有 1 列有效）：**

```
W_tile step0 = [ 0.1]         step0 部分积 = [ 0.25]
            [ 0.3]                      [ 0.29]
W_tile step1 = [-0.7]         step1 部分积 = [-0.44]
            [ 0.6]                      [ 0.35]

acc = step0 + step1 = [-0.19]
                      [ 0.64]
```

**两个 CTA 的输出拼接 = 完整 Y：**

```
Y = [1.12  0.23 | -0.19]
    [0.10  0.49 |  0.64]
```

与 §3 的结果**完全一致**——tiling 不改变结果，只是把同一个 GEMM 拆成「2 个 CTA × 2 步 K-loop」。

**接回物理读取**：这里 `BN=2`，2 个 CTA 读的是**同一块激活**（横向复用 = `N/BN = 3/2 → 2` 个 CTA 共读同一份 A_tile），而各自读**自己那片权重**（纵向各 1×）——结构与上面 1600 CTA 的真实 grid 一模一样，只是缩到了能手算核对的规模。

## 6. 量化粒度：per-token / per-channel / per-group

低比特存储（如 int8）时，用**缩放因子 scale** 在"整数 ↔ 真实浮点"之间换算。
scale 的**粒度**（一个 scale 管多少个数）决定精度与查表开销的平衡。沿用 §2 的小数据。

### 6.1 激活：per-token（每个 token 一个 scale）

激活按行（token）量化，一行一把尺子：

```
token0 scale = max(1.0, 0.5, 0.8, 0.2) / 127 = 1.0 / 127
token1 scale = max(0.2, 0.9, 0.1, 0.7) / 127 = 0.9  / 127
```

反量化：`X_hat[m,k] = q_x[m,k] * scale_x[m]`（shape `[M]`）。

### 6.2 权重：per-channel（每一行一个 scale）

每行所有 K 个特征**共用一个**缩放因子：

```
维度0: max=0.8 → scale = 0.8 / 127
维度1: max=0.9 → scale = 0.9 / 127
维度2: max=0.7 → scale = 0.7 / 127
```

反量化：`W_hat[n,k] = q_w[n,k] * scale_w[n]`（scale shape `[N]`）。

### 6.3 权重：per-group（每一行再切成小组，每组一个 scale）

设 group size **G=2**，每行 4 个特征切成 2 组，**每组一把尺子**：

```
维度0: 组0=[0.8,-0.2] max=0.8 → scale = 0.8 / 127
       组1=[0.5, 0.1] max=0.5 → scale = 0.5 / 127
维度1: 组0=[-0.3,0.9] max=0.9 → scale = 0.9 / 127
       组1=[0.2,-0.4] max=0.4 → scale = 0.4 / 127
维度2: 组0=[0.1, 0.3]  max=0.3 → scale = 0.3 / 127
       组1=[-0.7,0.6] max=0.7 → scale = 0.7 / 127
```

反量化：`W_hat[n,k] = q_w[n,k] * scale_w[n, k//G]`（scale shape `[N, K/G]`）。

### 6.4 对比

| 粒度 | 一个 scale 管多少 | scale 数量 | 精度 / 开销 |
|------|------------------|:---:|------|
| **per-channel** | 一整行（K 个数） | `[N]` | 粗；查表最省 |
| **per-group** | 一行内一段（G 个数） | `[N, K/G]` | 更细，更能贴合局部数值差异，精度更高；scale 变多，反量化查表开销更大 |

> 分组越细（G 越小），越能适应行内不同区段的数值范围，精度越高，但 scale 数量与
> 反量化时的查表/乘 scale 开销也随之上升。G=K 退化回 per-channel。
