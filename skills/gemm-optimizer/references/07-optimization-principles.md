# 07 · 优化原理：为什么 slc 有效 + GEMM 带宽优化的通用思路

> 一句话结论：decode GEMM 是带宽 bound，HBM 流量 = 一次性流过的权重 + 反复复用的激活 + 写回输出。
> 默认缓存策略下，大权重流把 L2 填满、把小激活逐出 → 激活每次复用都 miss 回 HBM，凭空多出一轮
> "激活流量"。slc（evict-first，`buffer_load` word0 bit17）告诉硬件"这批一次性数据缓存但优先
> 逐出"，把位置留给复用数据，bit-for-bit 无损。实测 bf16 gate_up 524MB M=32：-6.2%
> （422.4→396.3µs，1241→1323 GB/s，以 01/02 篇为准）。
>
> 本文讲这条因果链的三层（硬件 → 指令 → 运行条件）+ 新任务通用排查顺序；
> 数字全部以 01/02/03 篇已记录内容为准，不自造数字。

## 1. 硬件层：缓存层级与"污染"问题

### 1.1 gfx938（CDNA3）缓存链

| 层级 | 容量 | 管理方式 |
|------|------|----------|
| HBM | 峰值 **1.8 TB/s** | 带宽墙，memory-bound 的天花板（01 篇） |
| L2 | **8 MB**（全 CU 共享） | 硬件自动缓存，受 cache hint（slc/glc）影响 |
| L1 / LDS | LDS **64 KB/CU**（显式管理）；L1 是 `buffer_load` 走的硬件缓存 | LDS 只够 1 WG/CU，split-K 无空间（01/02 篇） |

64 个 CU。decode 算术强度 ≈ 2·M FLOP/byte，roofline 交点 M_ridge ≈ 155（560TFLOPS÷1.8TB/s），
**M < 155 全部 memory-bound**（M=32 带宽墙天花板仅 ~115 TFLOPS）：优化方向是**搬得更快**，
不是算得更快（01 篇判据）。

### 1.2 小 M decode GEMM 的流量结构（以 bf16 gate_up M=32 为例）

- 权重 N×K = 51200×5120×2B = **524MB**：**streaming**，每个输出 tile 读一遍自己那块，读完不再读（一次性）。
- 激活 M×K = 32×5120×2B = **327KB**：**复用**，被全部 N-tile 反复读，工作集小。
- 输出 M×N 写一次，占比小。

**"权重恰好全局读一遍"的推导**（winner kernel `MT128x32x128`，tile-M=128 / tile-N=32）：
M=32 ≤ tile-M=128 → **只有 1 个 M-tile**；N=51200 ÷ tile-N=32 = **1600 个 N-tile**，
每个 N-tile 只读自己那片 32×5120 的权重 → **权重总量恰好被读 1 次（纯流式）**；
而激活 327KB 被 1600 个 N-tile **各读 1 遍（复用 1600 次）**。

### 1.3 关键不等式与污染机制

权重 524MB **≫** L2 8MB（必然流过、不可能常驻）；激活 327KB **≪** 8MB（理可常驻）。理想：激活常驻 L2，权重流过不留痕，HBM 总字节 ≈ 权重 + 激活(一次) + 输出。

实际（默认策略）：权重的流式 load **填充 L2 cache line**，524MB 流过 = 反复冲刷 8MB，把激活的
line **逐出** → 激活下次被别的 N-tile 读就 miss 回 HBM。HBM 总字节多出"激活 miss × 复用次数"
项。**量化上限**：激活若每次读都 miss → 额外 HBM 流量 = 1600 × 327KB ≈ **524MB ≈ 权重流量翻倍**
（最坏 HBM 总流量 2×权重）；slc 后激活大部分 hit → 回到 ≈1× 权重（理想）。
**实测只拿到 -6.2%（01/02 篇），小于理论上限**：clean 下 LRU 本来就留下部分激活命中，且 HBM
读取与计算时间重叠。**-6.2% 不是天花板，只是当前 LRU 行为下的实测值**，别拿它当上限。

### 1.4 为什么这是"无损"优化

缓存策略只决定数据**从哪一级来**（L2 命中还是回 HBM），不改变数据内容本身：改后 kernel 输出
与原始 **bit-exact**（bf16 slc verify norm_error=5.57e-5，属 bf16 正常误差，02 篇）。这是 slc
相对 Layout A（重排权重、须 serving 侧配对）的根本优势：**只改二进制里一个 bit，零正确性风险**。

### 1.5 矩阵 tiling 图：复用从哪来（D = A × W）

> 📊 可视化版本（HTML/SVG，浏览器打开）：[`../assets/matmul_tiling_slc.html`](../assets/matmul_tiling_slc.html)
> 权重列 tile 绿 / 激活蓝 / 输出橙，红框高亮"当前迭代列"，右侧对照面板。风格参考 tilelang `MatmulExample.png`。

把 gate_up 的矩阵乘按 winner kernel 的 tile 切开看，就直观看到"谁一次性、谁被复用"：

```
 权重 W (K=5120 × N=51200, 524MB) —— 全局只从 HBM 读 1 次，每片用完即弃
 ┌──────────┬──────────┬──────────┬─────────┬──────────┐
 │  W₀     │  W₁      │  W₂      │   ⋯     │  W₁₅₉₉   │   每片 5120×32×2B (tile-N=32)
 │ 320KB  │  320KB   │  320KB   │         │  320KB   │   ← 每片恰好被 1 个 tile 用 (读 1 次)
 └────┬─────┴────┬─────┴────┬─────┴────┬────┴────┬──────┘
      │          │          │          │         │
      │   A (M=32 × K=5120, 327KB)     │         │
      │   ┌─────────────────────────┐  │         │
      └──>│  同一片 A, 被 1600 个列   ├─>│         │   ← A 喂给每一列 (复用 1600 次)
          │  tile 反复读             │  │         │      且只有 327KB, 装得进 8MB L2
      ┌───┴────┐   ┌────┐  ┌─────┐  │  │         │
      ▼        ▼   ▼    │  ▼     │  │  ▼         ▼
   ┌──────┐ ┌──────┐┌──────┐    ┌──────┐ ┌──────────┐
   │ D₀   │ │ D₁   ││ D₂   │ ⋯  │D₁₅₉₈│ │  D₁₅₉₉   │  输出 D (M×N), 写 1 次
   └──────┘ └──────┘└──────┘    └──────┘ └──────────┘
     N=0     N=32   N=64         N=51168  N=51200

   每列 tile_j 的计算:  D_j = A × W_j      (M×K)·(K×32)
```

读法：
- **横向 1600 列**（N 方向切 32 宽）：M=32 ≤ tile-M=128，所以纵向只有 1 行 tile，整个 GEMM = 1600 个列 tile。
- **每列只用自己那片 W_j**（5120×32×2B ≈ 32MB），读一次、用完不再碰 → 权重是"过路旅客"。
- **每一列都要完整的 A**（327KB）→ A 被读 1600 次 → A 是"常驻居民"。
- 结论（和 1.2 推导一致）：缓存里该保的是 A，该赶的是 W_j。slc 干的就是这件事。

（M 变大到超过 tile-M 时会出现纵向多行 tile，激活复用次数变成 (N/tile-N)×(M/tile-M) 但每个 M-tile 只读自己那片 A——"权重仍 1 次、激活复用"的结构不变，只是激活工作集变大，是否还装得进 L2 要按新数字重判，见 1.3。）

### 1.6 流程图：无 slc vs 有 slc（左右对照）

> **权重 = 过路旅客，激活 = 常驻居民；slc 是给旅客的"优先让座"标记，保证居民不被挤走。**

**精确点 1：slc 不是"不缓存"，是"缓存但最先被逐"（evict-first 优先级标记）。**
权重加了 slc 后**仍会进 L1/L2**（mmac 马上就要读，短期复用还是要的），只是 L2 腾位置时
权重行**优先被牺牲**。真正"不进 L1"的是 **GLC 位（bit16）**，本项目**没用它**——
不要把 slc 理解成 cache bypass。

**精确点 2：权重"全局恰好读一遍"是推导出来的**（见 1.2）：M=32 ≤ tile-M=128 → 1 个 M-tile；
1600 个 N-tile 各读自己那片权重 → 权重纯流式 1 次；激活被 1600 个 N-tile 各读 1 遍（复用 1600 次）。

```
 数据角色        流量特征                无 slc (clean)                     slc 加在权重 load 上
 ─────────────  ──────────────────      ──────────────────────────────     ──────────────────────────────
 权重 524MB     全局读 1 次              HBM ──> L2/L1 ──> VGPR ──> mmac     同左，但缓存行标记 EVICT-FIRST：
 (B-operand)    (1600 N-tile 各读一片)   L2 被权重行持续填充，                        权重行照常进 L2/L1（短期复用），
                    冲刷 8MB L2           激活行被权重行逐出 (LRU)                  但腾位置时权重行先被牺牲
 激活 327KB     被 1600 N-tile 各读 1 遍  N-tile #1:   HBM 读入 (首次 miss)      N-tile #1:   HBM 读入 (首次 miss)
 (A-operand)    (复用 1600 次)            N-tile #2:   L2 MISS (被权重逐出)       N-tile #2:   L2 HIT ← 短链路
                                       ...  大量回 HBM                            N-tile #3..1600: 基本 HIT
                                       最坏额外 1600×327KB≈524MB                激活常驻 L2，链路变短
                                       HBM 总流量 ≈ 2×权重                      HBM 总流量 ≈ 1×权重（回到理想）
```

**理论上限 vs 实测**：最坏 +524MB 冗余（2×权重）→ 理想 1×权重，理论空间是"把流量砍半"；
实测 bf16 M=32 只有 **-6.2%**（01/02 篇），差在：clean 下 LRU 已留下部分激活命中 + HBM 与
计算重叠。理论上限是分析工具，-6.2% 是这台硬件当前 LRU 行为下的实测值，**两者都别当"天花板"**。

## 2. 指令层：slc 位是什么

### 2.0 两个 operand 的路径不一样（slc 只落在权重这条上）

反汇编核实（`buffer_load` 直接进 VGPR，`ds_read_b128` 从 LDS 回读）：

| | 路径 | 关键指令 |
|---|---|---|
| **权重 W（B-operand）** | HBM → **L2/L1** → **VGPR** → mmac | `buffer_load`（idxen）直接 load 进 VGPR，`v_mmac` 直接从 VGPR 读（如 `v[96:127]`）——**不经 LDS** |
| **激活 A（A-operand）** | HBM → VGPR → **LDS** → ds_read → VGPR → mmac | `buffer_load` 进 VGPR，`ds_write` 写进 LDS，再 `ds_read_b128` 读回 VGPR 喂 mmac |

要点：
- **"权重直接到寄存器" ≠ 绕过缓存**。权重那条路中间**仍过 L2/L1 硬件缓存**（`buffer_load` 走的缓存），只是不碰 LDS。
- **slc 就作用在权重这条的 `buffer_load` 上**（它过 L2 那一级的 cache line），标记 evict-first。激活走 LDS，但它的 L2 命中/未命中仍由 LRU + 权重是否占位决定——slc 把 L2 留给它。
- 区分两组 load 才能只给权重加位（2.2 节），给激活加 slc 方向就反了。

### 2.1 两个 cache hint 位

gfx900 系 `buffer_load` 指令 word0 的缓存策略位：

| bit | 名字 | 语义 |
|-----|------|------|
| **bit17** | **SLC** | evict-first：缓存但**优先逐出**（本项目用的就是它） |
| bit16 | GLC | L1 无效，只走 L2（本项目不用） |

通用改法：`word0 |= 0x20000`，**不碰其他任何位**。策略位独立于寻址/宽度/LDS 偏移等字段，
不影响数值、不影响指令流 → bit-exact 无损。

### 2.2 两种指令形态都要会认（位位置相同，编码随指令变）

| 形态 | 特征 | 编码变化 | 主战场 |
|------|------|----------|--------|
| **lds 型** | prologue，直接写 LDS（`buffer_load_dwordx4 ... offen lds`） | `E05D1000 → E05F1000` | fp8 FusedMatmul |
| **idxen 型** | K-loop，向量索引加载（`... idxen`） | `E05C3000 → E05E3000` | bf16 Tensile Cijk K-loop（20 条） |

**两种形态的 slc 位都是 bit17，但"哪组 load 是流式读权重的大头"必须反汇编数清**：bf16 gate_up M=32
的 winner kernel（`Custom_Cijk_..._MT128x32x128_SE_K1_thread384`）里，prologue 只有 8 条 lds 型
（影响小），K-loop 里 **20 条 idxen 型才是流式读大权重的主体**（01 篇第 3 条、03 篇）。
**改错组（只改 prologue）= 收益趋零**。

区分权重 load 与激活 load：激活 load 有独立特征（如 0x8003xxxx / idxen SET 或不同 s-operand），
**只给一次性大流数据（权重）加 evict-first，复用数据（激活）保持默认**——给激活加 slc 等于
亲手把它逐出，方向反了。

### 2.3 与 C++ intrinsic 的对应（patch bit ≡ 改源码常量）

`__builtin_hcu_buffer_load_dwordx4(Para1, ..., Para5)` 的 **Para4/Para5 = glc / slc 缓存策略
常量**，都是**编译期常量**，直接折进指令 word0 的 bit16/bit17。因此：

**patch 二进制 word0 bit17 ≡ 把源码里 Para5（slc 常量）翻成 true 再重编译**，两者生成的
指令字节一致。这也是"改 bit 无损"的另一角度：策略位本来就不含数据依赖，只由常量决定
"从哪一级取数"。同理改 bit16 就是改 Para4（GLC），本项目不用。

## 3. 运行层：什么条件下生效 / 什么条件下是死路

### 3.1 生效判据（按此自检，全满足才上）

1. **存在 ≫ L2 的 streaming 数据**：权重 > 8MB（gate_up fp8 262MB / bf16 524MB 远超；
   qkv/o 小权重不满足 → slc 无效，01/02 篇）。
2. **存在 ≪ L2 的高复用数据**：激活/小规模输出（小 M decode 天然满足）。
3. **kernel 带宽 bound**：算力 util 低、有效带宽离 1.8TB/s 有距离（01 篇公式）；
   计算 bound 省字节没用。
4. **硬件响应 evict-first**：对照组实验——12 条 slc vs 201 条 slc 计时要有差；完全一样
   = 该 DCU/固件/DTK 不响应，**slc 路线该机判死**（03 篇诊断第 4 步）。
5. **改对了组**：operand 角色决定结论（见下）。

### 3.2 operand 角色不同，结论不互通（本项目核心教训）

| M | 权重的 operand 角色 | slc 结果 |
|---|--------------------|----------|
| 32/64（bf16 gate_up） | 流式 A 侧 load（idxen CLEAR / saddr-only） | **-6.2%（M=32，524MB）** |
| 128 | **B-operand / VGPR 路径（idxen SET）** | **回退 2.5%**（qkv/o M=128 实测，勿动） |

同一 kernel 族、同一 bit，换 M 就换 operand 角色 → 结论**不能跨 tile/跨 shape 迁移**，**换 tile 必须重新反汇编 + 重测**（02 篇"operand 专属，不跨 shape 迁移"）。

### 3.3 已知死路（02 篇清单，勿重走）

| 死路 | 原因 |
|------|------|
| slc 用在 M=128（B-operand, idxen SET） | 实测回退 2.5% |
| vmcnt(0)→vmcnt(4) 单独用（不配 Layout A） | no-op，依赖在途 load 结构改变才有效 |
| 权重 < L2（qkv/o 小 shape）上 slc | 没有污染问题，无字节可省 |
| split-K | LDS 64KB/CU → 1 WG/CU，无空间 |
| M=64 结构强塞 M=128 tile / 手写重写 B-load | 分别慢 29% / 回退 5% |

### 3.4 收益量级参考（全部来自 01/02 篇实测）

| case | 手段 | 收益 |
|------|------|------|
| fp8 gate_up（262MB） | slc | **-7.2%** |
| fp8 m128-down / m128-gate_up / m64-gate_up / m64-down | slc+W2 | -22.3% / -7.5% / -4.55% / -10.7% |
| **bf16 gate_up（524MB）M=32** | slc（K-loop 20 条 idxen） | **-6.2%**（422.4→396.3µs，1241→1323 GB/s，69.0%→73.5%） |

量级预期：几%~10% 区间。拿到两位数（如 -22.3%）通常说明原 kernel 污染更重或叠加了其他手段，
不是 slc 单兵能稳定复现的水平。

## 4. 通用思路：拿到一个新 GEMM 优化任务的排查顺序

> 原则：**先量化、后动手；一次只动一类手段；无收益进死路清单**。

1. **量化流量**：算清权重/激活/输出字节数（N×K×dtype / M×K×dtype）、激活复用次数（≈ N/tileN）、
   当前 µs → 有效带宽和算力利用率（01 篇公式）。先判带宽 bound 还是计算 bound：
   计算 bound 别在缓存上浪费时间，直接找算术强度或 tile 的问题。
2. **流量分类**：哪块 streaming（权重，一次性、≫L2）、哪块高复用（激活，≪L2）。
   决定"给谁加 evict-first"——给复用数据加 slc 是负优化。
3. **反汇编数 load 组**：找 streaming 数据的 load 组，数清**条数、形态（lds 型 vs idxen 型）、
   编码、operand 角色（A/B、idxen CLEAR/SET）**，确认复用数据的 load 组没混进来
   （特征见 2.2/2.3）。bf16 教训：大头在 K-loop 20 条 idxen 而非 prologue 8 条 lds
   ——**数错组，改完收益趋零**。
4. **上 evict-first（slc）做 A/B**：只改 streaming load 的 bit17（`word0 |= 0x20000`）。
   A/B 按 05 篇口径：`HIPBLASLT_TENSILE_LIBPATH` 指向**完整目录**（丢 Custom kernel 族
   会把 selection 变化误判成 patch 效果）、**交替顺序** ≥5 轮取中位、先跑硬件响应
   对照实验（03 篇诊断第 4/6/7 条）。
5. **slc 不够再往下走一层**（按风险递增）：
   - **访问模式/Layout**：权重物理布局能否让 load 合并成大事务（Layout A：改 3 个地址常量 + 权重重排配对，
     收益最大，serving 侧配对重排后重启才完整生效，03 篇铁律）；
   - **tile / occupancy**：每 CU 多少 WG、VGPR 占用、tile 数是否打满 64 CU（≪64 = 并行度不足的独立瓶颈，01 篇）；
   - **vmcnt**：vmcnt(0)→vmcnt(4) 放宽在途 load，只配 Layout A，单独 no-op；
   - **kernel selection**（本应最先试，零改动）：已有库有无更合适的现成 tile（实测：qkv M=128 → MT192x128x64，
     -14%，aiter `tuned_gemm.csv` 按名强制）。
6. **每步独立归因**：一轮只动一类手段；有收益保留、无收益回滚并记入死路清单（02 篇迭代纪律）。混改 = 说不清谁的贡献，等于没测。

## 5. 与其他手段的关系（一句话版，细节看 02-tuning）

- **slc** = 缓存策略（1 个 bit）：bit-for-bit 无损、零重排、最低风险，条件满足就上。
- **Layout A** = 权重物理布局重排：收益最大（-4%~-22% 区间），但必须 serving 侧配对重排。
- **selection** = 换现成 kernel：零改动零风险，**最先试**。
- **vmcnt** = 放宽在途 load 上限：依赖 Layout A，单独 no-op。

**推荐顺序：selection → slc → Layout A（+vmcnt），风险递增、潜在收益递增。**
每上一档前先确认低一档的判据为何不再满足，并做独立 A/B 归因。

## 6. 一页因果链（总结）

```
硬件限制        带宽 bound（M<155）+ 权重≫L2 + 激活≪L2
   ↓
污染机制        权重流填充 L2 → 逐出激活 → 激活每次复用 miss 回 HBM（冗余字节与权重同量级）
   ↓
指令位          权重 load 的 buffer_load word0 bit17 (SLC/evict-first) = "缓存但优先逐出"
   ↓
条件判据        权重>L2 ∧ 激活高复用 ∧ 带宽bound ∧ 硬件响应hint ∧ operand角色对 ∧ 改对组
   ↓
收益            省掉"激活冗余字节"：fp8 gate_up -7.2% / bf16 gate_up M=32 -6.2%（bit-exact 无损）
```

任何一步不满足 → 对应死路（第 3.3 节）；收益不达预期 → 第 4 节第 5 步往下走一层。
